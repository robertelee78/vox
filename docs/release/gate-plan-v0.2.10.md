# Gate plan: which proofs block a release, which become opt-in, and which go

This plan sorts all 157 tests in `integrate/v0.2.10` (69616f40) into one of three classes, using the decider's criteria:

- "Valid proofs block; rest optional."
- "Gates that increase CI without proving a product/feature actually works for a user, invalid."
- "Spike tests are valid" and "optional tests are valid."

The evidence for every test is in `gate-audit.md`, the read-only audit of the same tree. Nothing has been deleted or changed. **Nothing in the DELETE list should be removed until the decider approves it.**

### The 11 user-experienced timing bounds that become BLOCK with an apparatus clock

These come from the 22 tests the audit rated INVALID. Each bound is something a person experiences: a post arrives, a member appears, a service answers again. The defect each one catches is several times larger than the bound, so CI can measure it honestly once the apparatus clock exists. Each needs a same-timeline apparatus measurement: the time to spawn a no-op `vox`, the poll loop's maximum gap, or the time until the resumed process's socket first answers. When the apparatus exceeds its budget, the red says `CANNOT MEASURE: apparatus took X`; otherwise it says `PRODUCT: took X (apparatus Y)`.

`a_backed_off_peer_is_retried_when_due` (3 s), `a_burst_past_the_slot_cap_is_queued` (2/5 s), `a_dead_member_does_not_stall_the_room` (1 s against a ~30 s defect; widen it to the mechanism, e.g. 5 s), `a_lock_stops_a_join_in_flight` (10 s against 27.6 s), `a_member_whose_connection_died_is_synced_again` (10 s against ~20 s; also observe that the connection really was declared dead), `a_new_member_is_seen_promptly` (3 s), `a_relayed_host_restart_is_reached_again` (10 s against 25-32 s), `a_member_relays_what_it_learned` (5 s), `fetching_from_a_member_who_is_gone_does_not_stop_the_daemon` (2 s against an unbounded defect), `one_want_cannot_stop_a_room` (5 s), and `a_silent_stream_cannot_stop_a_node` and `a_vox_address_cannot_stop_a_node` (5 s against ~30 s).

## H: the shared-harness fixes every BLOCK test inherits

These fix most attribution gaps at once. In the table below, **"+H"** means the test needs these.

   - `:487` `until`: report elapsed time and the slowest poll.

   - `:399` `texts()`: an IPC error must fail `CANNOT MEASURE: control-socket read failed: {e}`, never return empty.

   - `:44`: label the kill failure APPARATUS.
   - `:252-262`: the same rule as `room.rs:384`: no retry; a failed join is PRODUCT.

   - `:126` `circuits()`: "no status line seen" must be CANNOT MEASURE, not 0.
