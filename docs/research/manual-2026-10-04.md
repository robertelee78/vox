# User-manual research supporting ADR-027

Research date: 2026-10-04. This record supports ADR-027; it is not another ADR or a user manual.

## Local evidence

- Bromure `manual/index.mdx`, `03-quick-start.mdx`, `17-troubleshooting.mdx`: clear first-use route,
  symptom headings, evidence before changes, Cause/Fix and escalation. Adopt the structure, not
  its product-specific log locations, reset advice, chapter count or diagnostics.
- hf2q.us `docs/adr/0004-build-time-guide-ingestion.md`, `src/content.config.ts`,
  `src/loaders/github-markdown.ts`, `github-markdown-policy.ts`: accepted build-time Markdown
  skin, bounded immutable download, AST validation, static render and provenance. Adapt to a
  whole manual by resolving one branch head, not each chapter's latest-changing commit.
- `/opt/unicornscan.org` has no website source in this local checkout; `/opt/hf2q.org` is absent.
  The verified reusable implementation is `/opt/hf2q.us`. Its CI verifies site pushes/PRs, not
  automatic production publication after an upstream documentation edit.
- voxlux.us already uses Astro 7.2.3, static HTML, shared navigation, copy controls, browser
  checks and public SHA-256 verification. Extend these; no framework migration is needed.

At the release ref, `crates/vox-tui/src/cli.rs` defines `--profile`; `room_cli.rs` handles the
control socket, closed rooms, live file offers and non-overwriting verified downloads;
`tunnel_cli.rs` distinguishes join reachability from refusal. `wake.rs` explicitly makes Codex
next-turn only, unlike supported Claude/OpenCode wake paths. The agent hook deliberately exits
successfully even on some integration failures: this is not a delivery receipt.

At the development ref, `client.rs` resolves node selection and the daemon log path; first access
can migrate an old layout. `doctor.rs` checks local setup without sending; its generic fallback
still says to start a profile daemon, so prefer the specific attach action from `daemonipc.rs`.
`ping.rs` sends protocol traffic but does not start an agent/model; timeout cannot isolate the
cause. `vox-core/src/node/api.rs` distinguishes an owed message body from a trust placeholder.
ADR-026 still names unfinished TUI migration; do not turn architecture intent into a release claim.

## External primary sources and their effect

- [Diataxis](https://diataxis.fr/): separate the reader's learning, doing, reference and explanation
  needs. Use a constrained first-success tutorial; do not replace it with generated CLI help.
- [Cloudflare troubleshooting guidance](https://developers.cloudflare.com/style-guide/documentation-content-strategy/content-types/troubleshooting/):
  use visible symptoms, consistent recovery structure, verification and an escalation route.
  This informs the template, not Vox's actual error meanings.
- [Astro content collections](https://docs.astro.build/en/guides/content-collections/) and
  [loader API](https://docs.astro.build/en/reference/content-loader-reference/): build-time remote
  loading and typed collection rendering fit the existing site.
- [OWASP logging guidance](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html#data-to-exclude):
  collect minimal diagnostics; keep credentials and key material out, and review identifying
  metadata. Do not promise automatic redaction without evidence.
- [W3C page structure](https://www.w3.org/WAI/tutorials/page-structure/),
  [reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html), and
  [focus visibility](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html):
  semantic headings, readable narrow layouts and keyboard-visible navigation are user outcomes.

## Rejected inferences

No response does not establish offline. Join refusal does not uniquely establish a bad
passphrase. A known message envelope without its body is not a generic trust marker. A plugin
generated successfully is not proof it is installed, trusted or delivering. A source-verified
command is not a proven walkthrough. Static skinning at build time is not a recurring publisher.
