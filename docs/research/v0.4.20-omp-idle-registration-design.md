# OMP idle registration recovery: source-bound design proposal

Status: design for review, not an implementation or approval. Scope is the OMP registration/availability boundary; ADR-029 and the aggregate RCA are owned elsewhere. Source observations below are from Vox baseline `ec00fa91b` and OMP source reviewed at `dc295ad286`; the proposed mechanisms and guarantees are design decisions, not observed behavior. No builds, tests, formatters, or real-profile runs were performed.

## The gap and existing boundary

**Observed:** `crates/vox-tui/assets/omp-extension.ts:253-308,418-477` starts register-only on activation/listen, suppresses the result, and a prompt only awaits an already-running registration. Its hook accepts exit 0 only if the spawning generation is still current; retirement increments the generation, rotates the route and kills children. Native OMP emits start, before-switch/branch/tree, switch/branch/tree and shutdown hooks (`/opt/oh-my-pi/packages/coding-agent/src/extensibility/extensions/types.ts:1833-1855`); its shutdown handlers have a short deadline (`runner.ts:154-173`).

`crates/vox-tui/src/agent_hook.rs:2382-2450` returns NoNode before constructing/storing the wake record, and returns DaemonUnanswered without staging it. Only the cold-daemon Starting branch stages the record. `host.rs:1621-1679` also stages an Attaching registration, and `host.rs:4090-4144` scans saved registrations when attachment is published. A Ready registration saves the record and schedules the Session opening (`host.rs:1701-1818`); that opening survives daemon restart from the saved record (`host.rs:1822-1824`). Therefore [INFERENCE] relying on that scan alone cannot restore an idle session after the NoNode or unanswered early return: there is nothing to scan.

The existing receipt is still exactly register-only exit 0 from the child spawned for this session and generation, with `current()` true at child close. The CLI maps register-only errors to failure (`crates/vox-tui/src/cli.rs:3358-3365`); `agent_hook.rs:2462-2504` rejects timeout, Attaching and refusals. No new receipt or upstream OMP change is needed. A withheld response, killed child, timeout, or superseded generation is **unknown**, not success and not proof of no daemon-side effect. Before a real prompt/use, coalesce a register if not confirmed; a recognized pre-envelope no-longer-registered failure invalidates confirmation and permits reacquisition, without poisoning an uncreated envelope. Do not treat a registration as proof that a room exists or that attention was delivered.

## Proposed smallest availability bridge

Add one narrowly scoped native Vox CLI watch mode, invoked as a child by this existing OMP extension, not a new runtime. There is currently no Subscribe-streaming CLI. It translates the existing authenticated `DaemonClient` protocol, and never registers, starts a daemon, attaches/unlocks a node, asks for credentials, reads room contents, or calls a model. The extension remains the only owner that calls its existing register-only hook. The child gets the selected node and an inherited parent-lifetime stdin pipe; its stdout has bounded newline frames `ready`, `unavailable` and `error` (fixed nonsecret reason categories only). No socket path, route/token, profile data or arbitrary daemon errors go to stdout, logs or model context; socket paths are private paths, not themselves credentials. Drain/cap stderr and surface a bounded sanitized category to the local operator. EOF on stdin terminates the child, including on OMP process death. Set child and all connections close-on-exec; no detached grandchildren.

1. Start exactly one active watcher per native extension instance before any registration writes; ordinary generation changes command it rather than spawn another. Connect with `DaemonClient::open`, bounded deadlines and no `ensure_daemon` or autostart. Read the authenticated hello's exact-fingerprint attached list, then close the short connection. The host's Attached state implies Ready. Never send `Nodes` or `Status`, which can explicitly attach passphrase-free nodes and defeat idle linger. Absence means unavailable; continue capped short hello probes. Creating, attaching or unlocking a node remains the operator's action, and unrelated node attach failures cannot block this observation.
2. If a probe suggests Ready, open Subscribe and await `DaemonFrame::Ok` **before** opening a separate fresh hello connection for the final attached snapshot. Buffer/coalesce intervening relevant events and resnapshot until none intervenes; events alone are not final state. Never use the subscription connection's pre-acknowledgment hello as final proof. Keep Subscribe only while the selected exact fingerprint remains attached; otherwise close it. EOF, timeout, malformed frames and protocol/version failures invalidate the observation.
3. The subscription server silently skips broadcast lag (`crates/vox-core/src/node/ipc.rs:7218-7233`): while subscribed take a serialized fresh hello snapshot on relevant events and at most every 30 seconds. While unavailable/unanswered use capped 1, 2, 4, 8, 16, then 30-second probe delay with at most one snapshot in flight. This is daemon availability reconciliation, not model/room polling. Detached passphrase-free nodes stay detached; manual detach is never undone. Probe gaps permit the one-second daemon linger to expire.
4. On Ready, while the current exact generation is unconfirmed, coalesce one register-only operation. Exit 0 plus current-generation close is its receipt. After typed transient registration failure, a fresh successful Ready snapshot permits another attempt at capped pace even if readiness never changed. Success stops retry; permanent refusal stays visible and does not respawn steadily. Same-generation retry is idempotent for exact node/session/route, never a room-message replay. Prompt/use and watcher callers coalesce.
5. A detach, failed subscription or failed snapshot makes confirmation unknown; reconnection and Ready reacquire via register-only, including after daemon restart. Durable registration is not itself a receipt. Serialize watcher messages and registration results in the extension event loop, fenced by instance, generation, session and branch. Helper spawn/pipe failure makes Vox unavailable, but ordinary OMP continues; no unfenced registration fallback is allowed.

On a handshake version/protocol mismatch, the helper exits with a distinct fixed category. The extension drains and retires it, resolves the current configured Vox binary anew and starts at most one successor for that mismatch episode at capped pace. If that successor also mismatches, stop and show update/reload guidance rather than looping or bypassing the handshake. Scope mismatch invalidation to that daemon instance, not all future daemon lifetimes. A later new daemon permits a fresh observation. Ordinary helper spawn/pipe failure remains visible and fail-closed, not permission for an unfenced fallback. Update while native OMP is idle must recover Ready and actual room delivery without a new prompt.

**Resource bound:** one watcher and lifetime lock per native extension instance, at most one subscription only in Attached/Ready, one short snapshot connection, one timer and one coalesced register child. Frames/stderr and request deadlines are bounded. No per-room fan-out, saved retry queue or generic retry framework. Shutdown closes stdin and children within OMP's deadline.

### Typed failures and protocol upgrade

The unchanged success ACK is not enough to classify current daemon-side prose-only `Failed` responses. Add a typed retryable registration refusal with a fixed reason enum and use it for both initial and deferred registration mutations. Preserve typed transient distinctions for NoNode, Attaching, Unanswered, NoDaemon, timeout, StillDetaching, registration-lock busy and Session ending; wrong identity, route, permissions and incompatible protocol are permanent. Client-side transport failures retain their typed classification. Do not parse `Failed` text or localized stderr. Map register-only temporary failure to distinct nonzero exit 75 and permanent refusal to 1, retaining other pre-existing categories; exit 0 remains the only successful receipt.

The new control IPC variant requires daemon IPC protocol 10 → 11 (`node/ipc.rs:78`). Keep strict version checks and the existing version-independent updater bootstrap working across the mismatch; do not bypass checks. Acceptance must exercise the actual v0.4.19 CLI/daemon upgrade cohort and subsequent Ready and Locked operator guidance, not a synthetic same-version approximation.

## Mandatory ownership prerequisite: in-flight writes, not merely callback fencing

Source exposes a separate race. Killing a register child does not retract a request already accepted by the daemon. `host.rs:1712-1729,4205-4219` can later store it; `wake.rs:842-899` replaces OMP transport fields with the incoming registration. A cold-start hook can also write directly (`agent_hook.rs:2433-2445`). [INFERENCE] An old request finishing after a session/branch switch can therefore overwrite a newer registration even though the extension correctly rejects its stale exit status. Existing prepare-side route matching (`agent_hook.rs:188-213`) protects consumption, but does not prevent that stale write from displacing the new route. Callback fencing alone is insufficient.

All new registration writes, including prompt registration and direct cold-stage writes, require one live current-generation fence. A reference-less old in-memory extension receives a typed **permanent** update/reload-extension refusal; disk setup refresh is not proof of the running extension's version. Doctor/status must explain restarting OMP and resuming the same conversation to load the refreshed disk extension. Failure to start or maintain the helper makes Vox unavailable for this extension while ordinary OMP remains usable, never an unfenced fallback.

Create a private instance directory under account-data `.daemon/omp-instances/<opaque-random-id>` with current-uid ownership, mode 0700 directories and 0600 files. Open and validate relative to trusted directory handles; reject symlinks, hardlinks, path traversal, unexpected owner/mode or unsafe file type. IPC and registration carry only an opaque instance ID and random generation reference, never an arbitrary caller-supplied path. Bind and recheck the actual current node fingerprint, session and generation; replacement fingerprint is a different node, never a fallback identity.

Use stable private per-instance **lifetime** and **mutation** lock files. The single watcher takes lifetime ownership once for its own lifetime. The existing node `registration_lock` cannot be the sole fence: NoNode, Attaching, direct cold staging and extension retirement cross node/process lifetimes and must serialize even when no node lock exists. The private instance mutation lock is the minimal common serialization point. Under it the watcher processes correlated revoke/install-generation commands and ACKs only after the requested record mutation; it does not exit on ordinary generation retirement. Before a transition the extension rejects old bridge work in memory, then waits for revoke ACK before installing a distinct fresh generation and registering it. On cancelled/rolled-back switch, reconcile the actual live OMP Manager, retire the provisional target and install a fresh valid generation even without a compensating event.

Every one of the three `store_checked` paths and every deferred registration write takes that same mutation lock, validates exact active instance/generation/node/session and verifies live lifetime ownership, holding mutation ownership through the write. Under mutation lock a writer tests a nonblocking exclusive lifetime acquisition: acquisition means no watcher owns it and the reference is invalid; a held lifetime lock plus matching record permits the write. Open/lock/validation errors refuse, never succeed. A hard watcher death or parent-pipe EOF invalidates the reference; the bridge rejects work and rotates the route immediately. A write already past its lifetime check can finish after death, so a successor waits for confirmed death/EOF and acquires/drains the **same** mutation lock before installing a distinct reference; it cannot reuse the old reference. Do not unlink or recreate either inode while any holder or waiter might use it. Cleanup is safe only after all in-flight owners have drained, otherwise leave it private.

A successor must acquire the same mutation lock, drain prior writers, acquire lifetime ownership and revoke the predecessor's record **before releasing mutation ownership**; this prevents lifetime-lock reacquisition from briefly validating an old reference. Mutation-lock contention is a typed temporary registration refusal. The extension owns directory cleanup after confirmed helper exit and all mutation owners/waiters drain; if it cannot establish that, leave the private directory in place rather than unlinking a live lock inode.

Unknown retirement fails closed and is surfaced. A request already accepted before watcher loss remains subject to existing route checks at materialization and commit. This is an OS-account boundary, not person attestation or a room capability. These are proposed requirements, not claims that child-kill or existing implementation solves the race.

## Consumer-facing acceptance and inverses

Use isolated fixtures and actual native OMP/Vox processes, not a real user profile. The room ask must be produced by a distinct authorized room participant and observed as actual attention in the exact idle OMP session; inspecting a registration file or an exit code alone is insufficient.

* Start native OMP with the selected node absent, allow initial register-only to fail, then create and explicitly attach/unlock that node and make its bound room Ready. Without any further OMP operator prompt, an authorized participant's urgent room ask reaches that same idle session and the agent observes it. Inverse mutant: disable the watcher/Ready-triggered register while leaving all else unchanged; the actual room ask does not reach the idle session.
* Repeat with the daemon present but initially unresponsive past the hook deadline, then make that same daemon answer with the selected node Ready; no new prompt, socket replacement, or daemon restart. The actual ask reaches the session. Inverse: suppress recovery observation/registration; it does not. Include subscription-before-snapshot race, daemon disconnect/reconnect, already-Ready snapshot, dropped event/periodic reconciliation and bounded probe counts.
* Pause an old registration after daemon request acceptance and switch, branch or tree to a different native route, including a return to the same session ID; then release the old request. Assert the old request cannot overwrite or reauthorize the successor and its late completion remains unknown. Exercise direct cold-start staging as well as daemon mutation, watcher parent-EOF cleanup and transition cancellation. Inverse mutant: remove the mutation-time generation fence and demonstrate stale overwrite or attempted authorization.
* Node absent, locked, detached or never Ready causes no automatic attach, unlock, passphrase request, room delivery or false registered status. A passphrase-free detached node stays detached and a manual detach stays effective. Verify persistent connections close and an autostarted idle daemon exits after its one-second linger despite bounded hello probes. An unrelated unreadable/failed node does not prevent observing the selected Ready node. A transient refusal followed by steady Ready retries after a fresh snapshot and eventually delivers without a prompt; confirmation stops retry. Permanent refusal remains visible without steady respawn. No unrelated OMP session is woken.
* Exercise each typed transient reason, including deferred lock-busy and Session-ending refusals, versus permanent wrong identity, route, permissions and protocol; verify exit categories and prove prose-only `Failed` is never parsed as a retry decision. Exercise all three `store_checked` paths plus deferred writes, prompt and cold-stage attempts, hard death/EOF after the lifetime check, successor drain, duplicate/late command ACKs, and cancelled transitions against the live Manager. Verify unsafe ownership paths/links/modes and replacement fingerprints are refused.
* Start an old reference-less in-memory extension after disk refresh: it receives the typed permanent reload refusal; doctor/status directs restart and resume of the same conversation, and ordinary OMP remains usable. Exercise real v0.4.19 CLI and daemon upgrading to the new version through the version-independent bootstrap, retaining strict version checks, then verify correct Ready and Locked guidance. No real user profiles.
* While OMP is idle update Vox and restart its daemon, then explicitly make the selected node Ready. The old watcher reports its mismatch category, retires and drains, and exactly one current-binary successor reacquires a fresh reference and delivers the actual room ask without an OMP prompt. A second mismatch gives visible reload guidance without a replacement loop; a genuinely new daemon instance is not permanently blacklisted by the earlier mismatch.
