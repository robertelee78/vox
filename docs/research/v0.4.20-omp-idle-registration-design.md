# OMP idle registration recovery: source-bound design proposal

Status: design for review, not an implementation or approval. Scope is the OMP registration/availability boundary; ADR-029 and the aggregate RCA are owned elsewhere. Source observations below are from Vox baseline `ec00fa91b` and OMP source reviewed at `dc295ad286`; the proposed mechanisms and guarantees are design decisions, not observed behavior. No builds, tests, formatters, or real-profile runs were performed.

## The gap and existing boundary

**Observed:** `crates/vox-tui/assets/omp-extension.ts:253-308,418-477` starts register-only on activation/listen, suppresses the result, and a prompt only awaits an already-running registration. Its hook accepts exit 0 only if the spawning generation is still current; retirement increments the generation, rotates the route and kills children. Native OMP emits start, before-switch/branch/tree, switch/branch/tree and shutdown hooks (`/opt/oh-my-pi/packages/coding-agent/src/extensibility/extensions/types.ts:1833-1855`); its shutdown handlers have a short deadline (`runner.ts:154-173`).

`crates/vox-tui/src/agent_hook.rs:2382-2450` returns NoNode before constructing/storing the wake record, and returns DaemonUnanswered without staging it. Only the cold-daemon Starting branch stages the record. `host.rs:1621-1679` also stages an Attaching registration, and `host.rs:4090-4144` scans saved registrations when attachment is published. A Ready registration saves the record and schedules the Session opening (`host.rs:1701-1818`); that opening survives daemon restart from the saved record (`host.rs:1822-1824`). Therefore [INFERENCE] relying on that scan alone cannot restore an idle session after the NoNode or unanswered early return: there is nothing to scan.

The existing receipt is still exactly register-only exit 0 from the child spawned for this session and generation, with `current()` true at child close. The CLI maps register-only errors to failure (`crates/vox-tui/src/cli.rs:3358-3365`); `agent_hook.rs:2462-2504` rejects timeout, Attaching and refusals. No new receipt or upstream OMP change is needed. A withheld response, killed child, timeout, or superseded generation is **unknown**, not success and not proof of no daemon-side effect. Before a real prompt/use, coalesce a register if not confirmed; a recognized pre-envelope no-longer-registered failure invalidates confirmation and permits reacquisition, without poisoning an uncreated envelope. Do not treat a registration as proof that a room exists or that attention was delivered.

## Proposed smallest availability bridge

Add one narrowly scoped native Vox CLI watch mode, invoked as a child by this existing OMP extension, not a new runtime. There is currently no Subscribe-streaming CLI. It translates the existing authenticated `DaemonClient` protocol, and never registers, starts a daemon, attaches/unlocks a node, asks for credentials, reads room contents, or calls a model. The extension remains the only owner that calls its existing register-only hook. The child gets the selected node and an inherited parent-lifetime stdin pipe; its stdout has bounded newline frames `ready`, `unavailable` and `error` (fixed nonsecret reason categories only). No socket path, route/token, profile data or arbitrary daemon errors go to stdout, logs or model context; socket paths are private paths, not themselves credentials. Drain/cap stderr and surface a bounded sanitized category to the local operator. EOF on stdin terminates the child, including on OMP process death. Set child and all connections close-on-exec; no detached grandchildren.

1. Once the bridge socket is listening and the main TUI session is current, activate exactly one watcher for the generation, and make the usual initial registration attempt. The watcher connects to the existing account daemon socket using `DaemonClient::open`, under a bounded handshake timeout, with no `ensure_daemon`/autostart. It opens a subscription connection and sends `DaemonRequest::Subscribe`; wait for `DaemonFrame::Ok`. On a **separate** connection send `DaemonRequest::Nodes`; find the exact configured node with `state == Attached` and `status == Some(Ready)` (`daemonipc.rs:128-176,291-292,390-395,474-488,2150-2171`). A node absent from the list, attaching, detaching, detached or locked is unavailable. A newly created node becomes eligible only after an operator attaches it and it is Ready; there is no automatic node creation or attachment.
2. Subscribe before snapshot; buffer/coalesce intervening events and take another snapshot after events received during the snapshot, until the snapshot has no intervening relevant event. Never trust an event as the final state. An Attached or Detached event for the selected node schedules a fresh Nodes snapshot. On an unavailable-to-Ready observation, emit one `ready`; an unavailable state emits at most one `unavailable` until state changes. Reconnect, subscription EOF/error, response timeout, protocol/version failure, or a malformed frame invalidates the observation and produces `unavailable`; re-establish subscription before a fresh snapshot. Do not treat Hello's attached list alone as proof of Ready.
3. The daemon's subscription server silently skips broadcast lag (`crates/vox-core/src/node/ipc.rs:7218-7233`), so subscribe/snapshot alone cannot guarantee observing every transition. While watching, issue a bounded, serialized Nodes health snapshot at most once every 30 seconds as well as on relevant events. This is a low-rate daemon availability reconciliation, **not** a model poll or a registration retry timer; it also detects a live subscription whose daemon stops answering and an Attached event silently lost to lag. During absent/unanswered daemon, retry connection/Subscribe/snapshot with capped exponential delay 1, 2, 4, 8, 16, then 30 seconds, with at most one connection attempt and one snapshot in flight. Reset delay on a complete responsive snapshot. Thus an already-existing but busy daemon that answers later is eventually discovered even without a new socket filesystem event, and a node created and attached after NoNode is discovered by its Attached event or the periodic snapshot. Responsiveness is conditional on the daemon eventually answering within the chosen timeout; permanent failure is displayed as unavailable, not reported as recovered.
4. On Ready, while the exact generation is unconfirmed, invoke one coalesced register-only operation. Exit 0 plus current-generation close is its receipt. Use documented typed nonzero categories for transient unavailability versus permanent identity/route/protocol refusal, never parse translated prose. A typed transient failure may retry on a fresh successful Ready snapshot at the capped pace even when readiness never transitioned: registration can fail while Nodes still answers. This is necessary for no-babysitting recovery and supersedes the earlier steady-Ready retry limitation. Repeated Ready after confirmation does nothing; permanent refusal stays visible without a steady respawn loop. Unknown same-generation retry is idempotent for exact node/session/route, never room-message replay. Prompt/use and watcher callers coalesce.
5. The watcher stays alive after confirmation. A matching detach, failed/closed subscription or failed snapshot makes confirmation unknown. On reconnection/Ready, reacquire via register-only, including after daemon restart; durable existing registration can be reopened by the host, but is not itself an exit-0 receipt for this generation. Serialize watcher messages and register results in the extension event loop, and fence each callback by generation, exact session, current branch and watcher instance. Register-in-flight and prompt attempts coalesce. Watcher failure/spawn failure is reported unavailable; do not claim no-babysitting availability when the helper cannot run.

**Resource bound:** one watcher per live generation, one subscription, at most one short-lived snapshot connection, one timer and one register child; bounded frames/stderr, finite handshake/request deadlines and capped probe rate. No fan-out by room or session and no saved retry queue. All callbacks ignore stale child output. Shutdown closes stdin/kills watcher and existing children promptly, without waiting beyond OMP shutdown's deadline.

## Mandatory ownership prerequisite: in-flight writes, not merely callback fencing

Source exposes a separate race. Killing a register child does not retract a request already accepted by the daemon. `host.rs:1712-1729,4205-4219` can later store it; `wake.rs:842-899` replaces OMP transport fields with the incoming registration. A cold-start hook can also write directly (`agent_hook.rs:2433-2445`). [INFERENCE] An old request finishing after a session/branch switch can therefore overwrite a newer registration even though the extension correctly rejects its stale exit status. Existing prepare-side route matching (`agent_hook.rs:188-213`) protects consumption, but does not prevent that stale write from displacing the new route. Callback fencing alone is insufficient.

The implementation must include a single local current-generation ownership fence covering **both** daemon registration mutation and direct cold-start staging. One concrete contract is a private per-extension ownership record plus a native interprocess lock, managed by the watcher: it records the active random route generation, is created before spawning register, and is revoked under that same lock before the extension activates the next generation. The old register passes an opaque generation reference through its existing environment/record; under the same lock the daemon (and the direct staging branch) checks that the reference is still active immediately before `store_checked`, and holds the lock through that write. On switch/branch/tree or shutdown the extension immediately marks the old generation ineligible in memory, sends watcher retirement, and does not start the next generation's register until retirement is acknowledged; retirement takes the lock, revokes the old reference, closes its subscriber, and exits. A cancelled native transition must reactivate/revalidate the still-current session rather than leave it unwatched. If the watcher dies or the process is killed, its lifetime pipe and native-owned liveness lease invalidate the reference; stale disk state alone is never authority. Route validation and mutation must be serialized with revocation; merely checking liveness before taking a lock is not sufficient. Each authority reference is scoped to exact extension instance, node, session and generation, random/unforgeable, bounded, and removed only when its owner releases it. A successor never adopts another generation's reference.

For that contract, use two different kernel locks on files in the owner's mode-0700 private directory: the watcher holds an exclusive **lifetime** lock continuously; all mutation and revoke operations acquire an exclusive **mutation** lock. While holding the mutation lock, a writer validates the exact active reference and tests that a nonblocking exclusive acquisition of the lifetime lock fails because the watcher still holds it; it then writes before releasing the mutation lock. The watcher revokes the reference under the mutation lock before releasing its lifetime lock. Treat inability to open, lock or validate as refusal, not success. A hard watcher crash releases its lifetime lock automatically: a later writer obtains it and must refuse. If it crashes after a writer's lifetime check, that write may complete; the successor must take the mutation lock, install its own distinct active reference, and register afresh. The checks apply again to any asynchronous deferred registration, not just initial request admission. Never unlink/recreate either lock file while a holder or waiter could still use its inode; directory cleanup follows retirement and final in-flight owners, or is left to existing private-directory cleanup. The extension must not activate a successor on failed/unknown retirement acknowledgement: surface unavailable and establish a new ownership instance only after the old watcher's exit/lifetime-lock release is known.

The extension must also treat watcher exit/pipe loss as immediate route retirement: reject wake and mirror requests for that generation and rotate its route before starting a replacement watcher. A watcher crash alone does not kill the extension's bridge socket; the bridge must explicitly enforce this condition. A request already accepted before that observation remains subject to the existing generation/route checks at materialization and commit.

This is an implementation prerequisite to review, not an existing protocol or a claim that the existing child-kill solves the race. It need not change the exit-0 receipt or introduce a general service, but it does require a small Vox-native registration/ownership change on both write paths. If the native ownership/lifetime fence cannot be made crash-safe and serialized at these mutation points, reject the design as incomplete; neither polling nor a successful late child exit is an alternative. Same-account access follows the existing local OS-account boundary, not person attestation.

## Consumer-facing acceptance and inverses

Use isolated fixtures and actual native OMP/Vox processes, not a real user profile. The room ask must be produced by a distinct authorized room participant and observed as actual attention in the exact idle OMP session; inspecting a registration file or an exit code alone is insufficient.

* Start native OMP with the selected node absent, allow initial register-only to fail, then create and explicitly attach/unlock that node and make its bound room Ready. Without any further OMP operator prompt, an authorized participant's urgent room ask reaches that same idle session and the agent observes it. Inverse mutant: disable the watcher/Ready-triggered register while leaving all else unchanged; the actual room ask does not reach the idle session.
* Repeat with the daemon present but initially unresponsive past the hook deadline, then make that same daemon answer with the selected node Ready; no new prompt, socket replacement, or daemon restart. The actual ask reaches the session. Inverse: suppress recovery observation/registration; it does not. Include subscription-before-snapshot race, daemon disconnect/reconnect, already-Ready snapshot, dropped event/periodic reconciliation and bounded probe counts.
* Pause an old registration after daemon request acceptance and switch, branch or tree to a different native route, including a return to the same session ID; then release the old request. Assert the old request cannot overwrite or reauthorize the successor and its late completion remains unknown. Exercise direct cold-start staging as well as daemon mutation, watcher parent-EOF cleanup and transition cancellation. Inverse mutant: remove the mutation-time generation fence and demonstrate stale overwrite or attempted authorization.
* Node absent, locked, detached or never made Ready must not cause automatic attach, unlock, passphrase request, room delivery or a false registered status. A failed/timed-out register stays unknown; identical Ready snapshots alone do not spin register children. A real prompt can retry once; a distinct later availability recovery can trigger one new attempt. Version/protocol errors remain visible and bounded. No unrelated OMP session is woken.
